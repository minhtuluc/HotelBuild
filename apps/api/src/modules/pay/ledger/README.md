# HB-093 — internal PAY ledger

`BookingLedger` is a port for authenticated, scoped command handlers, not a public endpoint. The caller supplies a **Prisma interactive transaction**, locks/rechecks the current actor, scope, booking version and policy decision, then calls the ledger before committing its command audit/outbox. Bare PrismaClient is rejected: autocommit statements cannot keep monetary locks. The ledger never starts/commits a transaction, performs PSP/network I/O, changes booking state, creates charges/receipts/refund requests or approves/pays a refund.

- `read(tx, bookingId)`: locks Booking, then all receipts ordered by UUID, then refund requests ordered by UUID. Reads the existing charge/allocation ledger and returns integer `bigint` VND values. All future PAY/BOOK writers must follow the same lock order before changing monetary rows. Serializable/repeatable-read conflicts and lock failures propagate; the caller rolls back and applies its existing transaction/idempotency retry policy.
- `sync(tx, bookingId, actor)`: validates and writes `paid_amount`, `refunded_amount`, `balance_due` only when changed, with `LEDGER_RECONCILED` audit in the same transaction. No change means no version/audit churn. Audit exposes scope IDs and decimal money strings, no guest/PSP payload.
- `reserve(tx, bookingId, requestId, legs, actor)`: reserves exact generated **NET**, using explicit successful original receipt IDs/amounts from the caller's policy/allocation decision. PENDING only, positive unique legs, zero NET uses no zero-value leg. Prechecks all sources before writing. Identical persisted allocation sets replay without new rows; different sets fail. Reservation audit, summary update and all caller work share rollback. This does not replace endpoint idempotency, maker-checker, refund eligibility or immutable cancellation basis.

`projectLedger` is pure: no time/IDs/I/O, no mutation, no rounding/policy. SUCCEEDED DEPOSIT/BALANCE/PENALTY/EXTRA_SERVICE/RESCHEDULE_FEE are collections; COMPENSATION is excluded; REFUND is negative outgoing. A successful refund must have a matching original-source leg. Partial APPROVED payout moves each proven successful leg from reservation to refunded once; other legs remain reserved, including unknown/failed attempts. REJECTED/CANCELLED release reservation while keeping historical rows. PAID needs every leg proven and exact NET. Applied allocations plus refunded plus reserved cannot exceed any successful receipt; each charge retains its own outstanding amount, so surplus/returned money is not automatically used for another room.

The ledger consumes persisted `booking_charges`, their `voided_amount`, and `payment_allocations.released_amount`. Caller HB-077/097/098 chooses and persists immutable room/night basis and releases/voids old allocations in the same transaction. This service does not redistribute receipts, invent prices/penalties, or turn legacy `total_amount` into missing charge rows. Active ROOM obligations must match the declared room total, and non-EXPIRED PENALTY obligations must match the declared penalty; incomplete legacy ledgers fail closed instead of publishing a false zero balance. CANCELLED/NO_SHOW exclude room debt, retain committed non-room fee/penalty obligations minus allocations; EXPIRED debt is zero per BR-BOOK-18. `balanceDue` includes unpaid penalty/fees once. Bigint is internal; any future JSON endpoint must convert to contract-safe integer money explicitly.
