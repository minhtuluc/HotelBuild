## 2. Đồng hồ, hạn mức và cách tránh "bom thời gian"

**Đồng hồ API là đồng hồ quyết định.** API được spawn với [`clock-shim.mjs`](../../tests/e2e/f7/clock-shim.mjs) (tái dùng từ HB-196): `Date.now()`/`new Date()` của tiến trình API cộng một độ lệch đọc từ tệp `QA_CLOCK_FILE`. Harness đặt lệch bằng `setClock()` của [`qa-f5-lib.mjs`](../../tests/e2e/f5/qa-f5-lib.mjs) trước mỗi cảnh, luôn tiến về phía trước và luôn rơi vào **đầu một phút** (helper `nextWindow()`).

- **Token TTL đọc đồng hồ tiêm, không phải giờ thật**: `signAccessToken` dùng `Clock` của API; `verifyAccessToken` so `exp` với cùng `Clock`. Bằng chứng trực tiếp: giải mã token của tài khoản `accountant` thấy `exp − iat = 900 s` và `iat` đúng mốc đồng hồ đã đặt; sau `+16 phút` cùng token trả 401. (Không thể "chờ thật" 15 phút trong một lượt chạy.)
- **Nhàn rỗi web cũng đọc đồng hồ API**: `AuthGuard.usableSession` từ chối phiên `OPS_WEB` khi `now − last_seen_at ≥ 15 phút`; `POST /auth/refresh` cũng chặn cùng điều kiện, nên client không "tự gia hạn" lách được. Vì vậy TC-AUTH-02 kiểm bằng `setClock +16 phút` rồi cho trình duyệt gọi request kế tiếp — đúng đường máy chủ. Hẹn giờ nhàn rỗi phía client (`createIdleWatcher`) và bộ đếm làm mới token của `createSessionClient` dùng **giờ thật của trình duyệt**; lượt này **không** giả lập chúng (`page.clock`), nên kết luận dựa vào máy chủ, không dựa vào bộ hẹn giờ UI.
- **"Bom thời gian" 60 giây của `LoginAttempts`**: hạn mức IP là **10 lần đăng nhập / 60 giây**, khoá Redis theo `floor(now/60000)` (dùng `Clock`, tức đồng hồ tiêm). Nếu dựng 5 lần sai + 1 lần đúng + 1 lần trên UI trong cùng ô, cộng với login của bước dựng dữ liệu, sẽ chạm 429 **sai chỗ** (429 không phải khoá tài khoản) và ca kiểm sẽ "nhiễu" theo phút đồng hồ thật. Harness vì thế nhảy sang **ô phút kế tiếp** trước mỗi nhóm login (`nextWindow()`), giữ mỗi ô ≤ 7 lượt; ca khoá dùng đúng 6 lượt + 1 lượt UI. Khoảng `locked_until − T = 900 s` đo trên cùng đồng hồ nên so được chính xác ±5 s.
- **CSDL/Redis**: mỗi lượt tạo CSDL riêng `hb117_qa_<hex>`, migrate + seed dev, và chỉ `FLUSHDB` **Redis DB 13** của lát cắt (không đụng DB 0–12/14–15). CSDL bị `DROP … WITH FORCE` khi xong.
- **Proxy cùng-origin**: mỗi web chạy `next start` trên cổng nội bộ, phía trước là reverse proxy của harness phục vụ luôn `/api/v1/**` từ API thật. Lý do ở phát hiện **F1-01**: API chưa cấu hình CORS, nên màn gọi API trực tiếp từ browser (SCR-15) sẽ hỏng nếu web và API khác origin; proxy giữ nguyên hành vi BFF/sản phẩm mà không tắt bảo mật trình duyệt.
- **Dữ liệu thử**: thêm 3 tài khoản `qa_f1_*` bằng SQL trong CSDL tạm (bản sao băm mật khẩu của `frontdesk`) để dựng đúng ca "FRONT_DESK scope CS-02", "tài khoản bị khoá" và "buộc đổi mật khẩu"; mọi thay đổi vai trò/phạm vi của `manager` được khôi phục ngay trong ca.
